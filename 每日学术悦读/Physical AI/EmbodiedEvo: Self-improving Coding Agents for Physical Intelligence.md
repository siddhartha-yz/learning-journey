# EmbodiedEvo: Self-improving Coding Agents for Physical Intelligence

**一句话：冻结底座模型，让编程 agent 在任务中试错，将经验提炼成代码技能和文字教训，再迁移到同任务的新布局。**

# 定位与动机

EmbodiedEvo 是具身编程 Agent 框架，不是新 WAM。主实验底座为 GPT-6-Astra（xhigh）。动机是：大模型虽然会规划，但抓取、条件检查和失败恢复不可靠；新实例又从零摸索，重复犯错。[1]

# 核心机制

练习：观察 → 写 Python 控制代码 → 执行 → 根据反馈修改。每个任务使用一个练习布局，可重置重试。

积累两类外部记忆：**Skills** 保存可复用操作程序；**Lessons** 保存适用条件、失败教训和检查规则。

测试：冻结这些经验，交给全新的 agent 处理同任务的新布局。当前执行代码仍可修改，但不能重置场景，也不跨测试实例积累新经验。动作经原生控制器执行，不依赖 VLA 生成。[1]

**Evo 指外部代码和经验随反馈被修订；没有更新模型权重，也不等同于遗传算法。**

# 关键证据

- 开发集匹配对照：相同执行模型、场景及任务描述输入下，加入经验后，类别平衡平均成功率从 **8.50% → 30.17%**。每任务仅 5 个测试场景。

- 论文全量仿真测试：得分 **44.48**，成功率 **37.82%**；记忆和开放指令较强，精细操作、长程执行仍弱。

- Skills／Lessons 相比原始交互历史，性能接近，测试执行成本降低 **53%**。[1]

2026 年 10 月 16 日查询的官方仿真榜为 **45.08／38.95%，第 1**，与论文 v1 数字不同，原因未核实；不能混用。该论文未报告真机实验。[1][2]

# 讨论结论

\*\*创新判断：\*\*代码技能库、外部记忆和反馈改进均有先例，如 Voyager。本文更有辨识度的是“单场景练习 → 冻结经验 → 新布局及跨模型复用”的组合与实证，机制新颖性有限；这是一项阅读评价，不是首创性定论。[1][3]

\*\*证据边界：\*\*对照支持“继承经验有用”，尚不足以证明这种经验组织方式优于各类成熟 memory 方法。榜首也不能证明等算力优势或操作能力全面领先。

\*\*泛化疑问：\*\*每个任务提前练习，主要验证同任务的新布局迁移，不能据此推出任意新任务泛化。按反馈改代码同样可能过拟合；应检查开发与测试隔离、对象及物理条件变化。针对任务适配不等于测试泄漏，目前没有据此认定作弊的证据。

**保留结论：模型不更新权重，也能通过外部经验改进行为；但经验有效、表示独特、跨任务泛化，是三个不同的命题。**
