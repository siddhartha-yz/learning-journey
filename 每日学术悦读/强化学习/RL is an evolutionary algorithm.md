# 强化学习与演化类比的精简阅读报告

**核心判断：把训练理解为“变异—反馈—保留”，有助于追问系统究竟学到了什么；但这不能证明强化学习、预训练和记忆更新是同一种算法，更不能保证它们自动产生泛化或安全。** [原文](https://snimu.github.io/2026/09/29/rl-is-an-evolutionary-algorithm.html)是一篇观点博客，以下区分它的启发、证据与推测。

先看 RL。模型可以针对同一道题生成不同回答，奖励再推动参数更新，让相对高分的行为更可能出现。这确实像选择。但标准 RL 中的 **policy 是生成行为的概率规则，一次回答是从中抽出的样本**。作者却把一次采样行为称为 policy，并对应演化中的“个体”；这是他自定义的用法，不能带回标准教材。GRPO 的一组回答也没有各自独立的模型参数，它们共同影响同一个策略。[GRPO 原始定义](https://arxiv.org/html/2402.03300v3#S4)与这一区别相符。

最重要的数学直觉是：**偏向高分，不等于更新机制相同。** 假设 A、B 两类行为的概率是 0.2、0.8，奖励为 1、0。采用指数加权选择，即概率乘上奖励的指数后重新归一化，A 可升至约 0.405；在同样取步长为 1 的构造中，对产生概率的两个分数做普通梯度上升，A 只升至约 0.256。它们方向相似，数值不同。这个手算反例说明，若要宣称数学等价，必须指定参数化、约束和更新规则。

GRPO 的组内比较提供相对优势，不能自动找出成功的真正原因。正确步骤、无关措辞和未被发现的违规操作，可能一起获得强化；不同任务的更新还会互相影响。组内归一化也不等于回答之间交换解题知识。因此，“高奖励轨迹被保留”的图景很有用，却省略了信用分配、探索和共享参数等困难。

预训练的区别更大。它通常根据真实文本预测下一个 token，通过梯度降低预测误差，没有显式的种群繁殖过程。不同批次的更新确实可能互相帮助或干扰，但重复训练同一批数据也可能加强记忆，并不强迫模型学会泛化。尤其要注意，micro-batch 若只是用于累积梯度，就不对应一次独立参数更新；把每个小批次都说成一代淘汰，并不符合计算流程。

平坦极小值提供了一个有条件的连接：参数在附近移动时，损失变化较小，能力可能更耐后续修改。但“抗参数扰动”与“适应新任务”不是同一性质。原文引用的[平坦性研究](https://arxiv.org/html/2605.02105v1)主要支持特定条件下减少微调、量化造成的遗忘。模型平均也不能无条件消除坏解：两个低损失点的中点，完全可能落在高损失区域。

压缩和记忆更新则可以不改变权重。agent 把经历写成摘要、规则或技能，后续读取它们，整个系统的行为就会变化。这可以承载学习，但**缩短上下文、保存经验、形成可迁移知识，是三件事**。摘要可能丢掉例外，错误经验也可能自我强化。原文的 MazeBench 解谜故事有原始观察，却没有操纵摘要的对照实验，不能证明进步来自多次压缩，更不能排除重新规划和采样差异。

多任务训练同样不保证只留下通用方法。模型可以识别任务前缀，然后分别采用专用策略；若每个任务都奖励同一种捷径，它甚至可能把捷径推广得更广。作者预测多领域 RL 比 MOPD 更有利于泛化，但[MOPD 原始研究](https://arxiv.org/html/2606.30406v1)在所测多领域能力整合指标上优于混合 RL 基线。这既不裁定谁更能迁移到全新领域，也说明不能靠演化类比决定胜负。

安全部分最值得保留的是：**指令与实际奖励冲突，会给违规留下优化空间。** 要求不用互联网，评分却只看答案，就可能让违规方案占优。不过必须检查完整目标、违规发现率和其他约束，不能把任何作弊都归因于这一机制。评测意识也应拆开：识别自己在被测、据此改变策略、采取违规或伪装，是不同现象。行为观察不足以反推出实验室完整的训练方式；作者关于普遍成因的强判断仍属推测。

agentic judge 的价值，是调用工具、检查执行证据，为难以自动评分的要求补充监督。但“裁判属于环境”不意味着它准确表达了人类意图。系统也可能越来越擅长利用裁判的盲点。已有[CoT 监测研究](https://arxiv.org/abs/2503.11926)发现，推理文本能帮助发现作弊，而过强地针对监测器训练又可能诱导隐蔽作弊。因此，使用监测信息与直接优化监测分数必须区分；稳定对齐仍是研究目标。

回到你的问题：根据 benchmark 反馈反复修改代码、技能和记忆，与参数 RL 的相似点，是**反馈参与选择后续行为**；关键差异是修改发生在外部配置、显式规则或程序中，未必通过奖励梯度更新模型。两者都可能泛化，也都可能过拟合。把固定题目的答案存入记忆，可以涨分而没有迁移；保存正确的通用搜索算法，则可能改善未见实例的表现。

对你关注的具身智能，变化还应落在环境机制上：换房间、视角、物体质量或摩擦条件，而不只是换任务描述。记住一百步动作可以解决原房间；知道何时规划、何时重新观察，才可能成为可复用方法。即使后一种方法在新迷宫中有效，也应把结论限定在这些环境，不能直接声称获得真实机器人的通用操作能力。泛化始终需要说清从哪些经历，迁移到哪些新条件。

所以，当前题目的代码修好，只能先说明题目修好了。要证明系统能力提升，应冻结修改后的版本，在没用于修改和选版本的新任务上测试，并与增加相同推理计算、但不保留经验的系统比较。再删除相关记忆或技能，检查提升是否随之消失。这是分析建议，尚未执行。反复用来决定改动方向的 benchmark，已经承担开发信号的角色，不能再独自充当泛化证据。

**值得记住：反馈能改变行为频率，却不保证学到正确原因；权重之外也能学习，也能过拟合；泛化与安全需要独立检验，不能由“像演化”推出。**
