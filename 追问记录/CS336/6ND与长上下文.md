## 1. 哪些条件会破坏 6ND 的近似？

**用户原话：**

> 6nd的算力法则一般什么条件下失效？简约

**AI 回答摘要：**

$C\approx6ND$ 是常规稠密模型全参数训练的粗略 FLOPs 估算，$D$ 指累计训练 token 数。长上下文的注意力额外成本、MoE 的激活参数量、冻结或 LoRA 改变的反向计算、激活重算，以及未计入参数量的大词表输出层，都可能使估算失准。FLOPs 也不能直接换成墙钟耗时。

## 2. 长到多少才需要单独计入注意力？

**用户原话：**

> 上下文长到什么数量级会不能忽略

**AI 回答摘要：**

原答以隐藏宽度约 4096–8192 的常规稠密 Transformer 为例：几千 token 时额外开销可能已可见，几万 token 时通常应单独核算。它强调这只是量级参考，阈值依赖宽度、架构、实现和允许的估算误差；单条序列长度也不是公式中的累计 token 数。

## 3. 既然几千 token 就偏离，百万上下文模型如何存在？

**用户原话：**

> 这么点开始就不能忽略了？现在都很多有1M上下文的大模型了。

**AI 回答摘要：**

AI 澄清：估算少算了一部分工作，并不表示工作无法执行。支持百万上下文，也不表示预训练的每条样本都长达百万 token。

FlashAttention 减少显存占用和数据搬运，但完整注意力的主要计算仍随序列长度平方增长。因此长上下文更需要单独计入注意力成本，而不能把前一轮量级例子当作模型的可运行上限。
